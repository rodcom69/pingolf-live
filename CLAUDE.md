# Pingolf Live

Pinball-golf scoring web app, live at https://playpingolf.com. It's static HTML/JS on GitHub Pages (this repo, `CNAME`) with Firebase Firestore (project `pingolf-95ba1`) as the database. There's no build step: push to `main` and it's live in about a minute. Pages cache for about 10 minutes.

This repo is public, so never commit PINs, secrets or personal details.

## Files
- `course.js`: the courses (holes, targets, ball counts) and the shared scoring code: `scoreRound`, `strokeRanges`/`chartStrokes`, closed-hole helpers, ranking (`compareScores`, `RANK_FINISHED_FIRST`) and event title/dates. **Bump the `?v=` on its `<script>` tag in index.html, admin.html and scoring.html whenever it changes**, or phones keep the old copy.
- `index.html`: the player app. It handles sign-in (name + 4-digit PIN), the scorecard, mulligans, the leaderboard, `#scores` (a shareable scores-only page) and `#tv` (the venue TV board, which shows a QR, pages through players and reloads every 3 hours).
- `admin.html`: the organizer page (PIN-gated) for events, hole closing, editing/voiding/adding scores, PIN resets and moving scores.
- **Location admins** (2026-11-26): `admin.html?loc=<id>` (short links `admin/<id>/` → redirect), ids + names in `LOCATIONS` and course→location in `COURSE_LOCATION` (course.js). Same page in location mode: own PIN (`secrets/loc_<id>`, set by the organizer on admin.html › Location admin PINs; never in code), sees only its own events, can start a new competition (New event, course limited to its own, test flag automatic), open/finish/edit its events, close holes, fix/void/add scores, hide players. No emails, moving scores, renaming or PIN resets. Writes are signed with `locUnlock/{id}` {loc, pin}; rules check `events/{id}.loc`. The organizer admin backfills `loc` on events when it loads. Adding a location = add to LOCATIONS + COURSE_LOCATION, then set its PIN.
- `scoring.html`: the printable scoring chart, hole cards and paper scorecard.
- Home-screen app (PWA): **removed 2026-11-26** (Rodney: not useful, clutters it up). No manifests or install tip. `sw.js` is now a self-removing worker (clears the old cache, unregisters) and index.html unregisters any old worker, for phones that installed the old app; keep both for a while. `icons/` still gives the favicon and apple-touch-icon (bookmark icon).
- Emails + IFPA numbers (both optional): asked on the welcome step; news checkbox (wording per course via `collectEmail.news`, default "Send me Pingolf event news"; X-Golf = "Send me Clubhouse pinball news"). Signed-in players get a one-time "Add your email" card, then a one-time "Playing Dec 12? Add your IFPA number" card (Save / No thanks each). Those two cards are remembered per phone/browser (localStorage `pingolf_email_<key>` / `pingolf_ifpa_<key>`; playerContacts is unreadable from the page) and are **not shown on home courses or Demo** (Rodney 2026-11-26). playerContacts may hold email and/or ifpa (int); saves merge. Admin table + CSV show IFPA. Sign-in has a "Forgot your name or PIN?" link: search registered names (fills in the sign-up key), PIN = ask the organizer (admin Reset PIN). "Email me my name and PIN" (top of the Forgot panel) POSTs to a Google Apps Script web app (`apps-script/Code.gs`, project "Pingolf PIN helper" in playpingolf@gmail.com, deployed as Web app / Execute as me / Anyone). It runs as playpingolf@gmail.com, which has Cloud Datastore Viewer (read-only) on the project, and mails the sign-in name + PIN to that address only; same answer either way; 1 email per address per 10 min. To change the script: edit in Apps Script, then Deploy > Manage deployments > edit > New version (the URL stays the same). Saved write-only to `playerContacts/{key}` {email, news, venue, at, proof} in its own batch after sign-in (can never block sign-in). admin.html › Player emails: Sign in with Google (Firebase Auth, Google provider, playpingolf.com authorized) → table + CSV downloads (all, or a venue's news list). The rules allow reading playerContacts only for the organizer's Google account uid.
- `firestore.rules`: the database rules. **Editing this file does nothing until it's published** in Firebase console › Firestore › Rules.

## Data (Firestore)
- `events/{id}` holds:
  - name, location, date, time (string), course, status (`upcoming|open|closed`), test (bool)
  - optional: `hiddenPlayers` (player keys taken off the public boards; scores kept; admin Hide/Show button), `closedHoles` (closed temporarily: no new entries, par unchanged), `removedHoles` (closed permanently: dropped, par goes down), `closesAt` (ms; stops new scores), `rankFinishedFirst`, `note`, `multiCard`
  - Events made by hand in the console must have **every** field the rules check, or admin saves fail.
- `attempts/{id}`: one score each, with playerKey, playerName, hole, strokes, method (`ball|chart`), eventId, ts, plus optional ball, rawScore, mulligan, void, card, editedByAdmin.
- `players/{key}`: `{name}`, the display name. `key` = the lowercased name the player first signed up with. To give someone a longer name, edit only `players/{key}.name` and keep the key, so their PIN still works. Admin "Rename" changes the key and separates the player from their PIN.
- `playerSecrets`, `secrets`, `playerUnlock`, `adminUnlock`: PIN plumbing. The organizer PIN lives in `secrets/admin`. Never type it, store it or put it in code.

## Rules of the game
- Par 3 per hole; strokes come from which ball hit the target, or from a chart when the target is missed (up to 8). Joker Poker is a 5-ball game.
- 2 mulligans, unlocked once every open hole is done. A mulligan replaces a hole only if it's better.
- Entering a hole is two steps: pick Ball 1/2/3 (or "Didn't make it" + final score, shown with commas as typed), then a confirm screen (what, strokes circle, low-score warning, mulligan/fix context) with Save / Change it. Nothing is written until Save.
- A failed save shows a red bar pinned to the bottom naming the hole; scores still unsent after 4s (weak signal) show a "keep Pingolf open" bar. Sign-in is name + PIN + Start. A name nobody has used opens a "Welcome! One more step" screen: shows the name, "I'm <existing name>" buttons for close matches, an optional email + news checkbox and optional IFPA number, then Create my player (nothing is written before that). Course pick (one app, one address): the phone remembers the last course picked, from the dropdown OR by opening a link (?e=, /pincrossing, /basement, QR), plus the day it was picked (`pingolf_event`, `pingolf_event_day`). A pick made today always wins; otherwise an open real event dated today (Dec 12) beats an older pick. Dropdown = open events that are real or whose course has `listed: true` (PinCrossing), plus link-only events this phone has opened (`pingolf_my_events`). Home courses (course `group: 'home'`, label `menuName`): Basement course = "Rodney's House"; "Michael's House" (renamed from "Michael R." 2026-11-26) = course `michael-2026` (8 machines, targets set from 370 guest games so an average guest game = 4 strokes, Michael approved 2026-11-25, all 3-ball incl. Bobby Orr + Stars (Rodney 2026-11-26), IPDB art in img/ (foo-fighters-pro, getaway-hs2, monster-bash-se, bobby-orr-power-play, stars, whirlwind, fish-tales; JAWS = pc-jaws); Foo Fighters Pro, JAWS Premium, Monster Bash remake SE; event `michael-test` created 2026-11-25 ("Michael R. Pingolf", Test + Open)); planned: "Joe F." (machine list pending). They're hidden from the public; a phone that has opened any home-course link gets a "Home courses" section in the dropdown listing all of them (Rodney 2026-11-25: don't confuse public users). Jump link for home courses: https://playpingolf.com/home (`home/index.html` -> `/?home=1`): sets `pingolf_home` (section unlocked) and opens the last home course used (`pingolf_home_event`), else the first open one. Logic is `eventListed` / `wantedEventId` / `pickerEvents` in index.html. The dropdown is styled as a switcher (`.course-pick`: "Course · tap to switch (N courses)" label, outlined box, "Switch ▾" pill; `appearance:none` so iPhone Safari doesn't render it as plain text). Rodney 2026-11-26: it wasn't obvious on iPhone that you can move between locations.
- Players can fix or undo a score only within 2 minutes; after that the organizer fixes it in admin.
- Public boards show first name + last initial. Your own phone and admin show full names.
- `multiCard` events (the Practice Open): after finishing a card, a player can start another, one at a time. Each card is its own board row ("Rodney C. Card 2"). Set with admin › event sheet › "Multiple cards" (defaults on for new home-course events). All home-course events have it on (Rodney 2026-11-25).
